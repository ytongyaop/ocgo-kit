# 架构

## 步骤
1. 从 PRD 功能清单倒推需要哪几层，只画用得上的，不为"以后可能要"预留。
2. 写 `docs/架构.md` 三段：层图（文本树即可）/ 依赖方向（外层依赖内层，单向）/ 每层的"做什么 + 不许做什么"。
3. 划内核与外围：内核 = 领域规则 + 编排，不依赖任何 IO；外围 = llm / 界面 / API / db / 知识库 / tools，按需取舍。
4. 每个不可逆或有代价的取舍落一份 `docs/decisions/NNNN-短名.md`，minimal MADR 五段：Title / Status / Context / Decision / Consequences，一页写完。
5. 建骨架，可直接抄 `work:templates/project-skeleton/` 的四层实例：`domain\` `app\` `infra\` `interface\`，外加 `docs\` `specs\` `tests\`。
6. 建 `docs/进度.md`（全 todo）。架构变 → 先更文档再改代码。

## 产出要求
- 层图能用一条规则解释：箭头只朝一个方向，出现反向依赖就是设计坏了。
- 每层都写了"不许做什么"，且至少一条是否定句（如"interface 里不许写领域规则"）。
- ADR 至少覆盖一次真实取舍：选了什么、放弃了什么、代价是什么。

## 边界
- 只做架构与骨架；不写业务实现、不排期。
- 不改既有项目代码；架构变更一律先文档、后代码。
- 硬规则见 `AGENTS.md#门禁`。

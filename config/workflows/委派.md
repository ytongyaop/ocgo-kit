# 委派

## 触发器表
| 事件（不是情绪） | 叫谁 | 判据 |
|---|---|---|
| 要读 ≥3 文件 / ≥200 行才知道答案 | explore | 只读定位、摘要 |
| 机械活且判据可脚本化 | 脚本 | 零 token、可重放 |
| 批量/脚本改过文件之后 | 跑 lint + explore 复核 | 全库最高危动作 |
| 报数字或"已完成"之前 | 脚本或 explore 先重数 | 数字要能贴命令输出 |
| 一次动 ≥5 文件，或碰 schema / 脚本 / lint | advisor | 结构性改动 |
| 第二次修同一问题 | advisor | 卡壳信号 |
| 两条路都说得通 | advisor | 关键取舍 |
| 正式验收 / 事故后 / 点名"高标准" | advisor 独立复核 | 高赌注 |
| 定稿 / 两轮以上 / 分歧 | final | 低频仲裁 |

## 步骤
1. 先试最便宜的：判据能脚本化就写脚本，不叫 agent。
2. 派活时说全 5 项：目标 / 范围 / 约束 / 可改文件 / 验证法。
3. 收回执只收四段：结论 + 文件行号 + 验证命令与输出 + 未决；不转贴全量日志。
4. 复核不过或改过两轮 → 升级一级，不原地重试第三次。

## 产出要求
- 任何数字附产生它的最后一条命令输出；贴不出就标"未验证"。
- 复核者比被验证者更可信：复核绝不外包给免费额度。
- 结论落定后同步更新 `docs/进度.md` 与相关 spec。

## 边界
- 只做调度与验收口径；不替 agent 动手干活。
- 硬规则见 `AGENTS.md#门禁`。

# 委派触发器 — 何时叫子代理

> 单一事实源。主管(主对话)按**事件**触发,不按情绪。原则:**执行可以省钱,验收不能自己给自己做。**
> 立此文件的原因:复盘发现主管几乎不叫廉价子代理,且三处失实全部发生在"自信区间"(自审漏掉)——错误与难度无关,与**赌注**有关。

## 0. 顺序(从便宜到贵,先试便宜的)

1. **确定性脚本** — 最快、零 token、可重放。凡判据可脚本化的对账,**一律写脚本,不叫任何 agent**。
2. **explore / general**(GLM-5.3-Flash / DeepSeek) — explore 做只读定位与摘要;general 做机械改动(改完立即跑 lint)。
3. **advisor**(GLM-5.3) — 结构性改动、第二次修同一问题、两条路取舍、**高赌注对账**。
4. **final**(Kimi K3.1 Pro,最贵) — 定稿 / 改过两轮以上 / 分歧仲裁,低频。

## 1. 触发器表

| 事件(不是情绪) | 叫谁 | 判据 |
|---|---|---|
| 要读 ≥3 文件 / ≥200 行才知道答案 | explore | 只读定位、摘要 |
| 机械活 + 判据可脚本化(清点/改名/查表/生成清单) | **脚本** | 零 token、可重放 |
| 机械复核但不易脚本化(数一遍/对一遍) | explore | 便宜、只读 |
| **批量/脚本改过文件之后** | **跑 lint + explore 复核** | 全库最高危动作(事故源头) |
| **向用户报数字或"已完成"之前** | **脚本或 explore 先重数** | 数字必须能贴出命令输出 |
| 一次改动动到 ≥5 文件,或碰到 schema / 脚本 / lint | advisor | 结构性改动 |
| 第二次修同一个问题 | advisor | 卡壳信号 |
| 两条路都说得通、要选一条 | advisor | 关键取舍 |
| **正式验收 / 事故后 / 用户点名"高标准"** | **advisor 独立复核** | 高赌注 |
| 定稿 / 改过两轮以上 / advisor 与 general 冲突 | final | 低频仲裁 |

- **不触发**:一句话能答的、纯闲聊、与当前工作无关的问答(不为一句话启动多代理)。
- **反直觉**:越自信越先对账——失实不在"卡壳"时,在"我觉得稳"时。

## 2. 任务分配(角色边界)

| 谁 | 干什么 | 绝不干什么 |
|---|---|---|
| **脚本** | 一切可判据化的对账与检查 | 需要判断的取舍 |
| **explore** | 只读定位、摘要、机械复核 | 改文件(那是 general 的) |
| **general** | 按已确认的规格/计划做实现、调试与验证,改完立即跑 lint | 自行扩范围、用自报"已完成"代替验证 |
| **writer** | 文档、PPT 文案、对外文字 | 技术判断、改代码、跑命令 |
| **advisor** | 复核、取舍、疑难 bug、第二意见 | 日常执行 |
| **final** | 定稿 / 多轮后 / 分歧仲裁 | 常驻 |

切分轴不是"轻活/重活",而是**"产出是否天然可机器校验 + 延迟是否可容忍"**。
**验证者必须比被验证者更可信** → 复核绝不外包给免费额度(质检负担会回流,且"审别人"恰好落在主管的自信盲区)。

## 3. 不靠自觉的机制

1. **如果你的知识库有 pre-commit 检查**:让它在提交前跑 lint,失败即拒绝提交(hook 放哪、怎么装按你自己仓库的约定)。
2. 数字/结论**必须能粘贴最后一条命令输出**;贴不出就标注"未验证"。
3. lint 自洽断言:声称查了 X,机器就必须真的查了 X。

## 4. 变更

- **建立**:经 advisor 复核;门禁第 4 条硬规则同时写进 `AGENTS.md`。
- **重构**:删掉早期独立负责闲聊的侧车子代理;explore 兼查资料;final 换成与 advisor 异构的仲裁模型;新增 writer(中文创作)。

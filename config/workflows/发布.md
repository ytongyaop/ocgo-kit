产出物: Conventional Commit、git tag、CHANGELOG.md、进度与归档记录

# 发布

## 步骤
1. 核前置：`git status` 看改动范围，测试输出还在手边，变更清单列全。
2. 写 Conventional Commit：`type(scope): 摘要`，body 写动机与影响；一次提交只讲一件事。
3. 里程碑打 tag：`git tag -a vX.Y.Z -m "…"`，与 CHANGELOG 条目对齐。
4. 更 `CHANGELOG.md`：按 Added / Changed / Fixed / Removed 归类，写用户可感知的变化。
5. 更 `docs/进度.md`：该功能/增量标完成，注明提交号。
6. 文档跟代码一起变：架构 → `docs/架构.md`，需求 → `docs/PRD.md`。
7. 整项目完结：明细迁 `work:记忆存档.md`，记忆只留一句摘要 + 指向，`记忆索引` 标"已完结"。
8. 一句话交代：这次改了什么、下一步是什么。

## 产出要求
- `git log --oneline` 一眼能看出这次做了什么，消息符合 Conventional Commit。
- tag 版本号与 CHANGELOG 首条一致。
- `docs/进度.md` 的完成标记带提交号，可追溯。

## 边界
- 只在用户确认后提交；不自行 commit、不 force push。
- 删数据、改权限、改全局配置单独停、单独确认。
- 硬规则见 `AGENTS.md#门禁`。

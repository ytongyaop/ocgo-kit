# 开发

## 步骤
### A 档：功能 / 大改
1. 写 `specs/<id>/spec.md` 五块：目标 / 边界（含"不做什么"）/ 可测验收标准 / 约束与依赖 / 未决问题。只写 WHAT+WHY，写完停下等确认。
2. 确认后写 `plan.md`（判据见下节），拆步 2–5 步，地板 2 步。
3. 确认后拆 `tasks.md`：一步一个可独立验收的增量，每步标出验证命令。
4. 一次只做一个增量：改 → 跑该步验证 → 贴输出 → 用户确认 → 下一步。高风险动作（schema / 删数据 / 权限 / 配置）单独停。

### B 档：bug / 小改
5. 先复现，记下命令与输出，写清期望 vs 实际。
6. 只动目标代码，边界写一句"不碰什么"。
7. 修完记 `docs/进度.md#修复记录`：现象 / 根因 / 改动 / 验证输出。

## 计划（plan.md 的六项判据）
- **拆步**：每步能独立跑通，步与步之间不留半成品。
- **改动清单**：写清文件路径；没列的就不许改。
- **每步验证**：一条能跑的命令或一次可观察的操作，不接受"看看没问题"。
- **回退点**：每步之后可回到什么状态（commit / 备份 / 开关）。
- **不碰清单**：这次明确不动哪些文件与模块。
- **风险与未知**：不确定的点标出来，不装作知道。

## 产出要求
- spec 的验收标准逐条可执行；plan 六项齐全。
- tasks 的每个增量都对应一条验收命令。
- 每步结束时能贴出当前命令输出，而非回忆。

## 边界
- 只做范围内实现；不重构无关代码、不顺手改风格、不扩大范围。
- 规格或计划要改 → 停下改文档，不擅自行动。
- 硬规则见 `AGENTS.md#门禁`。

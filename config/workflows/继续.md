# 继续

## 步骤
1. 认项目：从记忆实体、`docs/进度.md`、最近 `specs/` 找线索；拿不准就一次问清是哪个，不许猜。
2. 读状态：项目记忆实体 + `docs/进度.md`，再读最近一个 `specs/<id>/`，看停在规格、计划第几步、还是验收。
3. 一句话报进度："上次到 X，下一步 Y"，等用户确认再动。
4. 按停点接：停在规格 → 回 `开发.md` 写规格；停在计划第 N 步 → 从第 N 步实现；停在验收 → 回 `测试.md`。
5. 跑一次现状验证（项目定义的 lint / test，或 `git status` / `git log -1`），确认环境与上次一致再动手。
6. 状态与文档不符（代码改了文档没更）→ 先补文档再开工，不带着错状态往下。

## 产出要求
- 报出的进度能指到具体文件与步（如 `specs/001-x/plan.md` 第 3 步）。
- 恢复后明确写下一个增量及其验收命令。

## 边界
- 只做恢复上下文与接续；不趁机重构、不扩范围。
- 用户其实在闲聊或问别的 → 不套本流程。
- 硬规则见 `AGENTS.md#门禁`。

# 观察

## 步骤
1. 定观察窗（如 1 天 / 1 周）和三条关键指标：成功率、延迟、单位成本，写进 `docs/观察.md`。
2. 拉成本：从用量/账单页取一次数，记下口径（谁算、哪个时间窗）；估算不算事实。
3. 跑一次真实请求抓关键日志行；错误率按条数算，不按感觉算。
4. 对基线：写成涨跌百分比 + 一个原因假设，假设要可被下一次数据推翻。
5. 回退准备：确认回退命令可用（tag / 开关 / 备份），把命令原文抄进文档，不写"可回退"这种空话。
6. 指标越界 → 记现象与时间点，回 `测试.md` 补用例；需要回退就回退，再进 `开发.md` 修。
7. 观察窗结束写结论：达标 / 带条件达标 / 已回退。

## 产出要求
- `docs/观察.md` 含观察窗、三个指标、成本口径、基线对比、回退命令原文。
- 每个数字标明来源（页面 / 命令 / 日志时间）。
- 结论能回答"能不能继续放量"。

## 边界
- 只做观测与记录；不做值班承诺、不写 SLA、不擅自调参。
- 发现问题开修复流程，不在观察阶段顺手改代码。
- 硬规则见 `AGENTS.md#门禁`。

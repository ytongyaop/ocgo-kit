# 流程说明书:规格(新功能 / 大改)

**触发意图**:用户要给当前项目加一个新功能 / 大改(如"加个功能""做个…")。

**步骤**:

1. 生成 `specs/NNN-短名.md`(只写 `## 规格` 段),含 5 块:
   1. 目标
   2. 边界(做什么 + 明确**不做什么**)
   3. 可测验收标准
   4. 约束 / 依赖
   5. 未决问题
2. 规则:只回答 WHAT+WHY,不写实现(HOW);"不做什么"必须写;验收标准必须可测。
3. 生成后**停下**,等用户审改确认,先不要进计划。

**门禁**: 无可测验收标准不进计划;规格未确认不写代码。

**大改检查点**: 若属大改,回看 `docs/架构.md` 是否仍成立;架构变 → **先更文档再改代码**。需求变更 → 先改 `docs/PRD.md` 并写理由,不许代码里偷偷改。

**关联**: 当前项目记忆实体 + 其 `docs/进度.md`。注: bug / 小改走 **B 档**(免规格,守三条:明确边界含"不做什么"、只动目标代码、记入 `docs/修复记录.md`)。

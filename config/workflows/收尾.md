# 流程说明书:收尾

**触发意图**:功能通过验收,用户要收尾(如"收尾""提交""结项")。

**步骤**:

1. `git commit`(信息简短,对齐计划步)。
2. 更新 `docs/进度.md`,把该功能标为完成。
3. 若有 bug 修复,确保已记入 `docs/修复记录.md`。
4. 一句话总结这次改了啥、下一步做什么。

**维护纪律**:文档跟代码一起变(架构→`docs/架构.md`、需求→`docs/PRD.md`、状态→`docs/进度.md`);里程碑打 git tag;整项目完结 → 明细迁入你的记忆存档文件,MCP 只留一句摘要 + 指向。

**门禁**: 收尾必做 commit + 更新 `docs/进度.md`。

**关联**: 当前项目记忆实体 + `docs/进度.md`。若整项目完结 → 明细迁入你的记忆存档文件,MCP 只留一句摘要 + 指向。

# 测试

## 步骤
1. 把验收标准逐条改写成 Given/When/Then，一条标准至少一个用例。
2. 分档排序：先纯函数/单元（`pytest -q`），再集成，最后端到端；跑不起来的档写明原因，不假装跑过。
3. 逐条跑并留证据：命令 + 关键输出行 + 通过/未过。报任何数字前，先贴出产生它的最后一条输出。
4. 需要看交互/界面时用手动档，记录点击路径或截屏。
5. 未过项列清单：哪条、现象、疑似原因、建议下一步。全部通过才进 发布.md。
6. 回归一遍改过的旧用例，防止顺手改坏。

## 产出要求
- 每条验收标准都有结论：通过 / 未过 / 未验证（并写明为什么）。
- pytest 保留汇总行（passed / failed 数），失败的贴首个报错。
- 贴不出命令输出的一律标"未验证"，不写成通过。

## 边界
- 只做验证与取证；不顺手改实现（改是 开发.md 的事）。
- 不替用户决定"差不多就行"；不自审自签。
- 硬规则见 `AGENTS.md#门禁`。

# 自查手册

> 出问题时先别改配置。按这里的顺序查：先跑体检拿到证据，再对照症状表定位，最后才动手改。改完重启，再跑一遍。

## 先跑一次体检

两个脚本默认都不改任何文件（只有 `memory-lint.mjs` 显式加 `--update-baseline` 时才会写基线文件），在哪个目录下跑都行，在仓库根目录执行最省事。

**配置体检：`doctor.mjs`，12 项，查"装对没装对"。**

```bash
node scripts/doctor.mjs
node scripts/doctor.mjs --config-dir "~/.config/opencode"
node scripts/doctor.mjs --json > report.json
```

**记忆库体检：`memory-lint.mjs`，11 条规则，查记忆文件本身是否健康。**

```bash
node scripts/memory-lint.mjs
node scripts/memory-lint.mjs --memory "~/.config/opencode/memory.json"
node scripts/memory-lint.mjs --memory ./memory.json --archive ./记忆存档.md
```

没装 memory 就别跑第二个：`memory.json` 不存在时它会报一条 `FAIL 存在性` 并返回退出码 `1`——那是"文件还没有"，不是记忆库坏了。这套配置不装 memory 也能用，少了记忆，开场路由会自动降级成按类别的兜底路由。

**输出三档，含义不同：**

| 档位 | 意思是 | 该怎么做 |
|---|---|---|
| `PASS` | 这项核对通过 | 不用管 |
| `WARN` | 能用，但有隐患（可选功能没装、目录里多出的文件、`_说明` 没删） | 知道就行，想干净就顺手修 |
| `FAIL` | 硬错误，配置在这一项上不成立 | 必须修，否则对应功能不工作 |

**退出码**（两个脚本一致）：`0` = 没有 FAIL（可能还有 WARN）、`1` = 有 FAIL、`2` = 参数写错（比如 `--config-dir` 后面没给值）。

脚本末尾总有一行 `--- 汇总: PASS=n WARN=n FAIL=n ---`。想接进别的工具，用退出码判断成败比解析文本稳。

**输出长什么样**：表格模式每行四列、用制表符分隔——`档位`、`检查对象`、`规则名`、`详情`。详情里带 `→` 的那半句就是修复建议。

只想看硬错误，最稳的是 JSON 模式（机器可读，不受终端编码影响）：

```bash
node scripts/doctor.mjs --json > report.json
```

`report.json` 里 `ok` 为 `false` 就是有 FAIL；`checks` 数组里 `level` 等于 `FAIL` 的那几条，就是要修的目标。

也可以直接筛文本行：

```bash
# PowerShell
node scripts/doctor.mjs | Select-String '^FAIL'
# macOS / Linux
node scripts/doctor.mjs | grep '^FAIL'
```

一行都没有，说明没有硬错误，这时退出码也是 `0`。注意：脚本输出是 UTF-8；Windows PowerShell 5.1 在中文代码页下会把中文解成乱码，按行筛选可能不灵——这种终端请改用上面的 `--json`。

## 症状 → 排查

| 症状 | 最可能原因 | 怎么查 | 怎么修 |
|---|---|---|---|
| 会话选择器里只有 `build`，看不到 7 个角色 | 角色文件没装进 `<配置目录>/agent/`，或被装到了 `agents/`（复数）；也可能 `opencode.json` 的 `agents` 段没合并 | `doctor` 的 `agents advisor/final/writer` 那行，看是 3/3 还是 0/3，以及它报的目录路径 | 把 `config/agents/*.md` 复制到 `agent/`（单数），补上 `agents` 段里缺的角色，重启 |
| 改了 `AGENTS.md`，但行为没变 | 没重启；或改的是仓库里那份 / 项目级那份，不是配置目录里生效的那份 | `doctor` 的 `AGENTS.md 存在` 那行会打印它实际检查的完整路径 | 改 `<配置目录>/AGENTS.md`，改完重启 opencode |
| 提示有占位符残留 | 模板里的 `{{...}}` 令牌（`{{USER}}` / `{{CFG_ROOT}}` / `{{WORK_ROOT}}` / `{{KNOWLEDGE_ROOT}}` 等），或 `YOUR_USERNAME` / `<provider>` / `<你的...` / `<最便宜...` 这类旧写法没换完 | `doctor` 的 `占位符 无残留占位符` 会报 `文件:行号 占位符`（超过 8 处只列前 8 处并给总数） | 按行号逐个换成真实用户名、路径、模型 ID，重启 |
| `opencode.json` 解析报错 | 尾随逗号、写了注释、少了引号（JSON 不支持注释） | `doctor` 的 `opencode.json 合法 JSON` 那行；给不出精确位置时它会判断"尾随逗号"或"第 N 行有注释"，给不出就如实写"行未知" | 按提示删逗号 / 删注释 / 补引号；改不动就换个 JSON 校验器重新排版 |
| 某个角色起不来 | 对应 `agent/*.md` 缺失；或该角色 `model` 写了个套餐里不存在的 ID | `doctor` 的 `agents` 行（缺谁）+ `model 占位符` 行（是否还是 `<...>`） | 补文件；模型 ID 换成你套餐当前可用列表里的，重启 |
| 模型调用报错 / 提示额度不足 | 模型 ID 拼错、该档额度用完、或这个模型你没订阅 | 先看 `doctor` 的 `model` 行确认不是占位符；再到 opencode 自己的用量统计里看该模型是否可用 | 换一个等价模型 ID；临时把该角色指到主力模型，先把活干完 |
| MCP server 连不上 | 启动命令里的路径或包不存在（比如指向本地 `node_modules` 但没装）；或远程 MCP 需要凭据而未提供 | `doctor` 的 `memory MEMORY_FILE_PATH` 那行；opencode 启动时的报错里会带 MCP 名字 | 改成 `npx -y ...` 方式启动，或先把依赖装上；用不到就整段删掉那个 MCP 条目 |
| memory 不生效 | `MEMORY_FILE_PATH` 与 `AGENTS.md` 里写的记忆文件位置不一致；或该文件 / 父目录不存在 | `doctor` 的 `memory MEMORY_FILE_PATH`：会打印解析后的绝对路径和文件是否存在 | 两边改成同一个绝对路径；想立刻确认可用，手建一个空文件再重启 |
| 权限反复弹窗询问 | 工作目录没写进 `permission.external_directory` 的 allow；或路径键里还带 `<` `>` | `doctor` 的 `permission 路径键合法性`：含尖括号的键直接 FAIL，并指出是哪个键 | 换成真实绝对路径加进白名单；尖括号一律清掉，否则解析就失败 |
| 角色行为不符合预期 | 提示词没生效：文件放错目录，或 `opencode.json` 里也内联了同名 agent 的 `system`，两套定义打架 | `doctor` 的 `agents` 行确认文件实际位置；再打开 `opencode.json` 看 `agents` 段有没有同名项 | 一个角色只在一处定义：内联了 `system` 的删掉 `agent/*.md`，或反之 |
| `AGENTS.md` 里引用的流程文件打不开 | 死链——引用了不存在的 `workflows/*.md` 或 `docs/*.md` | `doctor` 的 `AGENTS.md 死链` 会列出 `路径(第N行)` 和总数 | 补上文件，或把引用改成实际位置。`docs/` 不在配置目录里，这类 WARN 通常可接受 |
| 门禁规则被模型当耳旁风 | `AGENTS.md` 里「门禁（硬规则）」那段被删或被改短 | `doctor` 的 `AGENTS.md 门禁四条`：缺 1~2 条报 WARN，缺 3 条以上报 FAIL | 照模板把这一节补齐（四条的原文以 `config/AGENTS.md` 为准） |
| 启动时报未知字段错误 | `opencode.json` 里留着 `_说明` 字段 | `doctor` 的 `_说明 字段` 那行（WARN 就是还在） | 删掉该字段，重启 |
| 体检报"配置目录不存在" | 路径写错；或 opencode 还没启动过，目录没生成 | `doctor` 第一行 `配置目录 存在` 会打印它找的是哪个路径 | 确认路径；用 `--config-dir` 指到真实位置；或先启动一次 opencode |
| `install.mjs` 跑完提示 `opencode.json 没有动` | 正常现象，脚本本来就不碰这份 JSON | 看它最后三行提示 | `opencode.json` 单独处理：按 `docs/01-安装.md` 的对照表手工合并，或用 `PROMPT.md` 让 AI 合并 |
| 主管不按 `workflows/` 里的流程走，直接开干 | 流程文件缺失，或 `AGENTS.md` 里的路由表指向的路径不存在（死链） | `doctor` 的 `workflows 9 个流程文件` 行看缺哪几个，`死链` 行看引用是否可解析 | 补齐 `workflows/*.md`；路径写错就把 `AGENTS.md` 里的引用改成实际位置 |
| 两台机器上同一套配置行为不同 | 模型 ID 不同（各自套餐可用列表不一样）、或额度/网络状况不同 | 各自的 `doctor` 输出对比 `model` 行；再看各自实际生效的模型 ID | 不追求完全一致：角色与门禁一致即可，模型 ID 按各机器可用列表填 |

## 几个高频问题

**为什么改了配置完全没反应。** opencode 在启动时读一次配置，运行中改文件不会热加载。所以"改了没效果"的第一嫌疑永远是没重启，第二嫌疑是改错了文件——项目级 `AGENTS.md`、仓库里那份模板、配置目录里那份，三者内容不同。`doctor` 会打印它实际检查的绝对路径，对照一下就知道改的是不是同一份。

**为什么同一个角色会有两套提示词。** 这套配置的规矩是"一个角色只定义一处"：`build` / `plan` / `general` / `explore` 写在 `opencode.json` 的 `agents` 段里，`advisor` / `final` / `writer` 写在 `agent/*.md` 里，两边不重复。两处都写同一个角色时，最终用哪一份取决于你那个 opencode 版本的合并规则（这里未验证），所以干脆只写一处：查出来留一处，另一处删掉，省得改了半天改在不生效的地方。

**为什么 `doctor` 报一堆 WARN，其实没事。** WARN 覆盖的是"可选功能没装"和"多出来的东西"：没装 memory、没有 `opencode.json`（模板还没落地）、`docs/` 引用找不到、`_说明` 没删干净。这些不影响 7 个角色和门禁规则运转。只有 FAIL 才说明某项配置不成立，必须修。

**为什么对仓库 `config/` 跑体检会 FAIL。** 模板里故意留着 `{{...}}` 令牌（`AGENTS.md` 里十几处），`占位符` 检查必然命中；如果把 `opencode.json.example` 原样复制成 `opencode.json`，`model` 检查也会因 `<provider>` 那类写法命中。这是给"还没装的人"看的模板，不是可用的配置。装到你自己的配置目录之后再跑，结果才有意义。

**为什么问一句简单问题也被套上流程。** `AGENTS.md` 的开场路由里有一条"跳出"规则：与当前工作无关的闲聊、日常问答不套流程，主管也可以直接答简单问题。如果它动不动就起子代理拆任务，通常是规则被改短了，或提示词里"简单问题直接答"那句被删了——对照模板补回去即可。

## 什么时候该重装

四个信号，出现任意两个就值得考虑重装，而不是继续打补丁：

1. `opencode.json` 已经改到自己看不懂哪些键是模板的、哪些是后加的。
2. `doctor` 从"只剩 WARN"变成大面积 FAIL，且逐项修不动。
3. 升级 opencode 之后多个角色、多个 MCP 同时报错，找不到单一原因。
4. 想从模板干净重开，只保留自己的模型 ID 和工作目录。

**重装前先备份整个配置目录**，不是单个文件：

```bash
# PowerShell
Copy-Item "$env:USERPROFILE\.config\opencode" "$env:USERPROFILE\.config\opencode.bak-20260101" -Recurse
# macOS / Linux
cp -r ~/.config/opencode ~/.config/opencode.bak-20260101
```

重装方式：`node scripts/install.mjs --apply --force` 覆盖三个映射的文件（`AGENTS.md`、`agent/`、`workflows/`），`opencode.json` 它依旧不碰，要你按 `docs/01-安装.md` 的对照表重做一遍。

注意两点：**重装不等于清空**——install 只复制不删除，配置目录里残留的旧文件要自己删；**重装完必须重跑 `doctor`**，把 PASS 当验收标准，而不是凭"感觉干净了"收工。

# 记忆模式

> 记忆只做一件事：让下一次会话知道这一次学到的东西。本文讲三档怎么分、实体怎么写、lint 查什么；具体预算与红线以 `config/AGENTS.md` 的「记忆加载」「记忆维护与 backlog」两节为准，检查口径以 `scripts/memory-lint.mjs` 的实现为准。

## 记忆解决什么问题（以及什么时候不该用）

跨会话会丢的东西，才是记忆该管的：项目正在哪一步、某个决定为什么这么定、上次踩过的坑在哪。这些事实一次写、多次读，且下次会话靠上下文拿不到。

不该进记忆的也很明确：

- **这次任务的细节**。改到第几行、报错原文、试了哪三种写法——这些留在当前上下文里就够了，任务结束即失效。
- **能从文件读到的内容**。代码、文档、配置本身就在磁盘上，把内容抄进记忆等于造了第二份事实源，两份迟早不一致。
- **过程记录**。复盘、排障、验收流水账属于存档文件，记忆只留结论和指针。

判断标准很朴素：**这句话下周三还有用吗？** 有用才值得占热层的位置；只在这次任务里有用的，写进上下文或文件。

## 三档怎么分

三档分的是"读取成本"，不是"重要性"。

| 档 | 在哪 | 什么时候读 | 预算 |
|---|---|---|---|
| 热层 | 记忆库里，少量固定实体 | 每次会话开头必读 | 合计有上限；单个实体也有上限 |
| 温层 | 记忆库里，其余实体 | 先按关键词检索，命中才读 | 单实体有上限，无整体上限 |
| 冷层 | 存档文件（`.md`） | 只在需要追溯时按指针定位读 | 不进上下文，只受文件本身约束 |

热层是唯一"每次都要付钱"的部分，所以它必须小。判断一个实体该在哪一档，看的不是它多重要，而是**多常被用到**：每次开场都要用的（索引、教学约定、流程路由表、当前用户偏好）放热层；偶尔查一次的项目实体放温层；已经完结的项目整段转冷层，记忆里只留一个指向存档的指针。

热层超预算的处理方式不是"删点不重要的"，而是"把细节挪进存档，实体只留结论"。热层的价值在信噪比：塞进去的每一条无关信息，都会稀释真正要紧的规则。

预算的具体数字写在 `config/AGENTS.md`；脚本里另有几个更细的阈值，见下面的对照表。

## 每个实体必须有什么

三个字段，缺一不可，且必须出现在观察行的**行首**（脚本按行首匹配，写在句中不算）：

- `状态：`——这个实体现在是什么状况，**必须带日期**。没有日期的"进行中"，过一个月就没人知道它是否还成立。
- `边界：`——管什么、不管什么。写清边界才能避免两个实体抢同一件事，也才能在检索时判断该读哪一条。
- `明细：`——指向存档的指针，形如 `明细：某存档.md#某小节`。记忆里放结论，展开的内容在存档里。

示例形态（内容为示意）：

```
状态：2026-01-01 起进行中，当前卡在规格确认
边界：只负责这个项目的进度与决策记录，不含代码细节
明细：记忆存档.md#项目进度
```

另外两条硬约束：

1. **一条观察 = 一个原子事实**。一条里塞三件事，检索时命中一条却要读三倍内容，改状态时也无法只改其中一件。
2. **有长度上限**。超了就拆成两条。上限的数值见对照表最后一行；先写后修不算数——脚本对"新写入超长"直接判 FAIL。

## 写入闸门

写之前先查，写完再核。顺序不能反：

1. **先查重**。调 `add_observations` 之前，用 `search_nodes` 搜一遍关键词。已有实体就往上加观察，不要新建一个近义名的实体——记忆按名字索引，重名和近义名会让同一件事分裂成两份。
2. **超长先拆**。写之前逐条看长度，超过上限的当场拆成两条再写。写完发现超长再改，等于自己给自己开罚单。
3. **改状态用"新增 → 核对 → 删旧"**。记忆接口没有原地编辑，所以改状态是三步：先加新状态，确认新状态写得对、日期对，再删旧的那条。跳过"核对"就会出现新旧两份状态并存，下次会话无法判断哪份有效。
4. **过程进存档，结论进记忆**。复盘、排障、验收流水账写进存档，记忆里只留结论和指针。

写完跑一次 lint，有 FAIL 就修完再说"维护完成"。

## 什么时候清理

清理不是想起来才做，而是按固定节奏走：

- **每次对话结束前**：只补新的稳定事实，顺手跑 lint。
- **每周**：处理 lint 的 FAIL 和 WARN——超预算、索引死链、索引漏登、重复观察、过期状态。不需要全量通读记忆库。
- **每月**：完结的项目转冷层（记忆里只留索引项和指针），清理失效的关系，另做一次恢复演练（从存档能否重建出记忆）。

三条红线，触发就该动手：热层出现复盘或排障日志，必须降级到存档；临时状态超过 30 天未复核，不得再标"当前"；项目完结或 30 天未访问，转冷层。

**lint 有 FAIL 时，不得宣称维护完成。** 这是唯一一条把"体检结果"和"对外说法"绑在一起的规则。

## lint 会查出什么（11 条规则对照表）

`scripts/memory-lint.mjs` 只读，不加参数时默认读配置目录下的记忆文件，输出 `PASS|WARN|FAIL|INFO` 开头的行加一行汇总，退出码 0 表示无 FAIL、1 表示有 FAIL、2 表示参数错误。

| # | 规则 | 查什么 | 报什么级别 |
|---|---|---|---|
| 1 | 解析与存在性 | 记忆文件是否存在、能否读取；每行是否合法 JSON；记录 `type` 是否为 `entity` / `relation` | 文件不存在、读不了、某行解析失败、未知记录类型 → FAIL；全部通过时报实体数 / 关系数 → PASS |
| 2 | 实体重名 | 实体名按大小写不敏感归组，同名出现多次 | 每组每个名字各报一条 → FAIL |
| 3 | 关系端点 | 每条关系的 `from` / `to` 是否都能在实体里找到（大小写不敏感） | 指向不存在的实体 → FAIL |
| 4 | 命名规范 | 实体名是否以 `user:` / `project:` / `tool:` / `protocol:` / `state:` 开头 | 不合规 → WARN |
| 5 | 三字段 | 观察里是否存在**行首**的 `状态：` / `边界：` / `明细：`（全角半角冒号都认） | 缺哪个字段写哪个 → WARN，每实体一条 |
| 6 | 索引死链与漏登 | 是否存在名字含「记忆索引」的实体；索引里 `【类型】xxx` 或 `【索引】xxx` 指向的实体是否存在；其余实体是否在索引文本里出现 | 找不到索引实体、索引指向不存在的实体（死链）→ FAIL；实体未登记（漏登）→ WARN |
| 7 | 分层预算 | 按 `--hot-pattern` 正则分热层 / 温层（默认 `记忆索引\|教学约定\|工作流路由表\|^user:`，大小写不敏感）后量字符数 | 热层单实体超 3,000 → WARN；温层单实体超 4,000 → WARN；温层实体观察条数超 40 → INFO（仅诊断，提示该拆或删旧没执行）；热层合计超 8,000 → FAIL，未超 → PASS |
| 8 | 热层进展日志 | 热层实体里，非三字段的观察是否含「已完成 / 已通过 / 已交付 / 复盘通过 / 验收通过 / 已提交 / 刚刚 / 今天」 | 命中 → WARN，报命中条数 |
| 9 | 重复观察 | 同一实体内是否有完全重复的观察（大小写不敏感） | 有重复组 → WARN，报组数 |
| 10 | 存档指针 | `明细：xxx.md` 指向的文件是否存在；带 `#小节` 时存档里是否含该小节。未给 `--archive` 时整条跳过 | 存档文件不存在 / 读不了 / 指针文件不存在 / 小节不存在 → WARN |
| 11 | 单条长度（原子性） | 每条观察的字符数是否超过 160；与 `--baseline` 里的哈希比对区分存量与新增 | 存量超长只报 INFO（列 top5 供分期消化）；未豁免的新写入超长 → FAIL |

几条与脚本实现相关的口径，容易踩：

- **字符数按 UTF-16 计数**（中文算 1，emoji 算 2），与配套的 PowerShell 版保持一致，不要用 code point 数去对账。
- **热层由正则决定**，不是由名字写死。改了 `--hot-pattern`，热层合计和进展日志两条的检查范围都会跟着变；输出里会列出被判为热层的实体名，就是为了让口径可见。
- **豁免靠哈希**。`--update-baseline` 把当前超长观察的哈希写进基线文件，之后同样的文本不再报 FAIL；改了一个字就是新哈希，重新 FAIL。这个开关必须同时给 `--baseline`，脚本不猜写盘位置。
- **索引引用的两种写法都认**：`【user】名字` 这类带类型前缀的，和 `【索引】名字`。写别的格式脚本看不见，会被判成漏登。

## 不装 memory 会怎样

配置照常工作，只是降级：

- **流程路由**：`config/AGENTS.md` 的兜底是"记忆不可用就明确报告「记忆服务未连接」并停止路由，不猜、不用旧记忆里的映射表"。`workflows\` 下的 9 个流程文件还在磁盘上，用户点名流程或说清意图时照样能走，只是不能按具体项目检索；拿不准就先问用户。
- **门禁与角色**：完全不受影响。角色分工、档位、门禁四条都在纯文本里，与记忆无关。
- **跨会话上下文**：这是唯一真正的损失。上一个会话定下的决定、踩过的坑，下次不会自动回来，需要你自己在开场说明，或让 AI 先读仓库和存档。
- **lint**：没有记忆文件可查，脚本会报文件不存在（FAIL）并继续跑完其余检查。这时候这条 FAIL 不代表记忆坏了，只代表没装。

判断要不要装：如果用法是"一次会话干完一件事"，不装更省事；如果长期在同一个项目上反复开工，装的收益来自"不用每次重新交代背景"。

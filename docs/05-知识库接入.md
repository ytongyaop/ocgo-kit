# 知识库接入

> `references` 是可选配置。接一个知识库，就是给它一个目录加一份 schema，告诉模型"这里有资料可查、什么任务该来查"。不接也完全不影响 opencode 运行。

## 要不要接

判断标准只有一条：**这批资料以后还要反复查吗？**

- 要反复查：长期维护的笔记、文档、论文与摘要、踩坑记录。值得接。
- 只用一次：临时下载的 PDF、一次性的需求文档、随手存的截图。放进对话让 AI 现读就行，不用为它建库。

库的成本不在磁盘，在**维护**：schema 要写、页面要更新、索引要同步。资料量还没到"翻不过来"的程度就建库，只是给自己加活。

## 最小可用结构

三层就够，多一层都是负担：

```text
<库根目录>/
├── raw/          原始资料：只增不改
├── wiki/         AI 维护的页面：可重写
└── AGENTS.md     schema：这个库怎么用
```

两条不变量比目录名重要：

- **`raw/` 只增不改。** 原始资料是事实来源。改了它，就没法回头验证"当初资料是这么写的"。要修正结论，写进 `wiki/`，不是改 `raw/`。
- **`wiki/` 可以整篇重写。** 它是从 `raw/` 加工出来的产物，允许被更好的版本覆盖。

目录名随便换，这两条不能换。

## schema 该怎么写

库根目录的 `AGENTS.md` 是模型进入这个库时**第一个读**的文件。它至少要说清五件事：

1. **目录职责**：每个目录放什么、谁写、能不能改。
2. **页面命名规则**：文件名长什么样，主题重名怎么处理。
3. **每页必填字段**：缺了哪些字段就算没写完。
4. **新建页还是更新页**：什么情况另开一页，什么情况改现有页。
5. **禁止事项**：明确写"不要做什么"，通常比写"要做什么"更管用。

一个虚构示例（主题是园艺，纯属编造，不要照抄内容）：

````markdown
# 园艺工具笔记 — schema

## 目录
- `raw/`    原始资料，只增不改
- `wiki/`   加工后的页面，可重写

## 命名
- 页面名用「主题 类型」，如 `堆肥 方法.md`；一个主题只留一页，确有分叉就加限定词，不用 `-2`

## 每页必填
- 来源：`raw/...` 或「派生自某页」
- 更新：`YYYY-MM-DD`

## 新建还是更新
- 主题已有页面 → 更新那一页
- 主题是新的、能独立成文 → 新建
- 只有一两句观察 → 追加到相关页末尾，不单开

## 禁止
- 不改 `raw/` 里的任何字节
- 不写没有来源的结论，拿不准标「未证实」；除总目录外不建额外的导航文件
````

关键不是格式，而是**每条规则都能被一眼判定**。"页面质量要高"没法执行，"每页必须有来源和更新日期"可以。

## 怎么让 opencode 认识它

在 `opencode.json` 里加 `references`，一个库一项，只有两个字段：

```json
{
  "references": {
    "<库名>": {
      "path": "<库根目录的绝对路径，正斜杠>",
      "description": "<什么时候该读这个库、进去先读什么>"
    }
  }
}
```

- `path`：绝对路径，用 `/`。JSON 不支持 `~` 展开；模板里写作 `{{KNOWLEDGE_ROOT}}`，换成你的知识库绝对路径（例如 `C:/Users/你的用户名/knowledge`）。
- `description`：**写给模型看的路由提示**，不是给人看的介绍。要写清"处理哪类任务时该进来、进来先读哪个文件"，否则模型不知道什么时候用它。写成"我的笔记"等于没写。

改完重启 opencode 才生效。不需要了就整段删掉。

## 和记忆的区别（别混用）

| | 记忆 | 知识库 |
|---|---|---|
| 存什么 | 跨会话的事实与状态：谁在做什么、做到哪一步 | 可反复检索的资料 |
| 什么时候读 | 每次开场，按索引定位 | 碰到相关任务才读 |
| 谁写 | 对话过程中顺手记 | 有资料要摄入时才写 |
| 体量 | 小，越精越好 | 大，允许很厚 |

两个常见错放：

- **把笔记塞进记忆**：记忆是热路径，每次开场都读。把长文塞进去，等于每次对话先背一遍笔记，信噪比直接崩掉。
- **把项目状态写进知识库**：知识库是资料层，不是进度表。"这个功能做到哪了"属于记忆或项目文件，写进知识库会让资料页变成流水账。

## 不接会怎样

没有任何影响。

`references` 是可选配置项，删掉整段，opencode 照常启动，其余能力一个不少——只是模型不知道有这个库存在，需要你手动指路径。

所以顺序应该是：先用一阵子，确实在反复翻同一批资料了，再建库、再配 `references`。反过来先建库再找用途，多半留下一个没人读的空目录。

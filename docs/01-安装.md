# 安装

> 三种装法，从省事到可控：让 AI 装、用脚本装、手动抄。任选一种，装完都用 `node scripts/doctor.mjs` 收个尾。

## 前置条件

装之前先确认三件事，缺哪件先补哪件：

1. **opencode 已安装**。运行 `opencode --version`，能打印出版本号就说明装好了。没有这个命令，先去 opencode 官方文档按你的系统安装，装好再回来。
2. **Node 18+**（只在两处需要）。运行 `node --version`。需要它的地方是：`memory` 这个可选 MCP 服务、以及本仓库 `scripts/` 下的三个脚本。没有 Node 就跳过 memory，其余配置照装。
3. **知道你的配置目录在哪**：
   - Windows：`%USERPROFILE%\.config\opencode`，即 `C:\Users\<你的用户名>\.config\opencode`
   - macOS / Linux：`~/.config/opencode`
   - 设过 `XDG_CONFIG_HOME` 的，以它为准：`$XDG_CONFIG_HOME/opencode`

   这个目录通常是**第一次启动 opencode 之后**才生成。不明白就先启动一次，或自己建个空目录。

下文出现的 `<配置目录>`，都指上面这一条解析出来的绝对路径。

## 方式一：让 AI 装（推荐）

打开仓库根目录的 `PROMPT.md`，把里面 `text` 代码块的**整段提示词**复制走，粘给你正在用的 AI（Claude Code、opencode、Cursor 都能用），并把本仓库放在它能读到的目录里。

它按作业单执行，关键顺序是：

- **先检查**：opencode 版本、Node 是否可用、配置目录的绝对路径，打印出来给你确认。
- **先看后动**：先列出配置目录里已有哪些文件、仓库 `config/` 里有哪些文件，两份清单并排给你看，等你说"开始"。
- **先备份**：任何已有文件被修改前，先复制一份 `<原文件名>.bak-YYYYMMDD-HHMMSS`。
- **只增不覆盖**：`AGENTS.md` 逐节对比，只补你缺的章节；`opencode.json` 保留你原有的 `mcp` 和 `permission`，只新增模板里有而你没有的键。
- **合并结果过目后才写盘**：`opencode.json` 合并后的完整内容先贴给你看，确认之后才写入，写入前还校验一次是不是合法 JSON。

适合不想手动改文件、也不想自己判断"哪段该保留"的人。

## 方式二：用脚本装

在仓库根目录执行。三种用法，**默认不写任何文件**：

```bash
# 1) dry-run：只打印计划
node scripts/install.mjs

# 2) 真正安装：已存在的文件跳过，只补缺的
node scripts/install.mjs --apply

# 3) 覆盖已存在文件：覆盖前先备份成 .bak-YYYYMMDD-HHMMSS
node scripts/install.mjs --apply --force
```

配置目录不在默认位置时加 `--config-dir`（三个脚本都支持 `~`，Windows / macOS / Linux 通用）：

```bash
node scripts/install.mjs --apply --config-dir "~/.config/opencode"
```

脚本只做三件映射，和下面的手动对照表完全一致：

- `config/AGENTS.md` → `<配置目录>/AGENTS.md`
- `config/agents/*.md` → `<配置目录>/agent/`（注意是单数 `agent`）
- `config/workflows/*.md` → `<配置目录>/workflows/`

**它不会碰 `opencode.json`。** 这份 JSON 要按人个性化合并（模型 ID、工作目录、要不要 memory），脚本不做，交给方式一的 `PROMPT.md`，或按方式三手工合并。

退出码：`0` 成功（dry-run 也算成功）、`1` 执行期出错（某个文件没复制成功，已做的备份不删）、`2` 参数写错。

## 方式三：手动抄

| 从仓库 | 到配置目录 | 说明 |
|---|---|---|
| `config/AGENTS.md` | `<配置目录>/AGENTS.md` | 全局规则，对所有项目生效 |
| `config/agents/*.md` | `<配置目录>/agent/` | 目录是**单数** `agent`，装错成 `agents/` 角色不会出现 |
| `config/workflows/*.md` | `<配置目录>/workflows/` | 8 个流程文件 |
| `config/opencode.json.example` | 复制成 `opencode.json` 后改 | 见下 |

`opencode.json` 的改法：先把模板复制成 `<配置目录>/opencode.json`，再逐个替换占位符——

- `YOUR_USERNAME`：换成你的系统用户名。模板里它出现在权限路径、memory 启动路径、`MEMORY_FILE_PATH`、`skills`、`references.vault.path` 等处，**一处都不能留**。
- `<provider>/<最便宜的 fast 档小模型>#fast`：`title` / `summary` 两个角色的模型 ID，换成你套餐里最便宜的快速小模型。
- `opencode-go/...` 开头的模型 ID：不算占位符，但只是"档位示例"，要换成你套餐当前可用的等价模型。
- `_说明` 字段：整段删掉。它不是有效配置项，opencode 不读它，只给人看。
- `references.vault`：用不到就整段删掉。

若你**已经有一份** `opencode.json`，只合并缺的键，不要整份覆盖：`mcp` 和 `permission` 保留你自己的写法，`agents` 段只补你没有的角色。

> memory 那段示例用的是本地 `node_modules` 里的启动脚本；`PROMPT.md` 第 8 步给的是 `npx -y @modelcontextprotocol/server-memory`。两种都有人用，以你实际安装方式为准——关键是 `MEMORY_FILE_PATH` 指向的绝对路径要和 `AGENTS.md` 里写的记忆文件位置一致。

## 装完怎么确认

四条，都能自己观察：

1. 重启 opencode 后，会话选择器里能选到 **7 个角色**：`build` / `plan` / `general` / `explore` / `advisor` / `final` / `writer`。（`title` / `summary` / `compaction` 是隐藏维护代理，不出现属于正常。）
2. `<配置目录>/AGENTS.md` 存在，里面有「门禁（硬规则）」那一段。
3. `<配置目录>/workflows/` 下有 **8 个 `.md`**。
4. 重启后开个新会话，问"你受到哪些规则约束"，回答里能提到门禁与角色分工。

再跑一次体检脚本，它会逐项核对上面这些，外加占位符、JSON 语法、memory 路径、权限键、模型 ID 等，共 12 项：

```bash
node scripts/doctor.mjs
node scripts/doctor.mjs --config-dir "~/.config/opencode"
```

每行输出 `PASS` / `WARN` / `FAIL` 三档，末尾一行 `--- 汇总: PASS=n WARN=n FAIL=n ---`。

**全部 PASS、或只剩 WARN，就算装对了。** 出现 FAIL 是硬错误（占位符没换、JSON 不合法、`AGENTS.md` 不在正确位置之类），按那一行 `→` 后面的提示修。

> 直接对仓库的 `config/` 目录跑体检会出 1 个 FAIL：模板里故意留着 `<provider>` 占位符。这是正常的；装到你自己的配置目录之后再跑，才是真实结果。

## 装错了怎么退回

`--force` 覆盖（以及 `PROMPT.md` 第 3 步）都会先备份，文件名是：

```
<原文件名>.bak-YYYYMMDD-HHMMSS
```

例如 `AGENTS.md.bak-20260101-093000`，就躺在原文件同一个目录里。同一次 `install.mjs` 运行中，所有备份共用同一个时间戳，好认。

还原就是把它复制回原名（会覆盖被改坏的那份）：

```bash
# PowerShell
Copy-Item "AGENTS.md.bak-20260101-093000" "AGENTS.md" -Force
# macOS / Linux
cp AGENTS.md.bak-20260101-093000 AGENTS.md
```

新增出来的文件不用备份也不用还原，直接删掉即可——`install.mjs` 只复制、不删除，你原有的东西不会因为它消失。

还原完记得重启 opencode；配置改动只在重启后生效。

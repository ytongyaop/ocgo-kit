# ocgo-kit PRD

## 一句话定位

> 一个 OpenCode Go 订阅，养起 7 个分工明确的 AI 角色，不开第二个 API Key。

一份可读、可抄、可改的 opencode 中文工作流配置。不是插件，不是产品，是个人实践的开源分享。

## 给谁用

- 已订阅或打算订阅 OpenCode Go 的个人开发者
- 中度使用：每天几小时，不是 24 小时挂机
- 在中国网络环境下工作，被"多开 API、多充余额、配代理"消耗过
- 想读懂自己配置的每一行，不接受装个插件当黑盒

## 解决什么

| 痛点 | 普遍做法 | 本仓库做法 |
|---|---|---|
| 多模型分工要开多家 API | 每家各充一次、各管一个余额 | 一个 Go 订阅全覆盖，角色与模型档位对应关系已给出 |
| 智能体配置零散 | 抄 prompt 片段，越堆越乱 | 7 个角色 + 9 个流程 + 门禁规则，成体系 |
| 出问题不知从哪查 | 反复重装、换模型瞎试 | doctor 自检脚本 + 故障树手册 |

## 明确不做

1. 不做 opencode 插件，不写 TypeScript 扩展，不发布 npm 包。
2. 不含任何具体使用者的项目内容、业务代码、笔记。
3. 不打包第三方 skill，只给上游链接。
4. 不含任何 API Key、token、账号标识。
5. 不追求与 oh-my-opencode 功能对等；Linux 支持不承诺完善，v1 为 Windows 优先 + macOS 说明。
6. 不做黑盒一键安装：install 脚本必须打印它改了哪些文件。
7. 踩坑章只写搭建本配置体系的坑，不写业务开发踩的坑。

## 额度数据的处理原则

不公开任何真实金额、真实月度消耗、后台用量截图。

文档只写相对策略：哪个角色配哪个模型档位、为什么、可以怎么替换。
所有涉及数量的描述必须标注"个人经验，非承诺"，不构成任何效果保证。

## 维护与更新节奏

- 本仓库随 opencode 版本、模型迭代、社区反馈持续更新，不设固定周期。
- 不承诺功能对等、不承诺长期支持、不承诺问题响应时间。
- 欢迎提 issue 说"我这里跑不通"，但不保证修复。
- 版本变化导致配置失效时，优先保证 README 和安装文档可执行。

## 成功标准

| # | 标准 | 判定方法 |
|---|---|---|
| 1 | 零隐私泄露 | 用仓库外的私有敏感词表执行 `grep -riF -f <敏感词表>.txt .`，返回空 |
| 2 | 首屏可懂 | 陌生人读 README 前三段能说出本仓库是什么、给谁 |
| 3 | 能装起来 | 干净环境按安装文档操作后，opencode 中出现 7 个 agent |
| 4 | 能自查 | `node scripts/doctor.mjs` 输出 PASS/WARN/FAIL 汇总，异常时退出码非 0 |
| 5 | 能抄走 | `config/` 下每个文件可独立复制使用，不依赖其他文件 |

## 附录：文档职责边界（避免重复）

- README 只说：是什么、给谁、和 omo 的区别、怎么开始。不展开细节。
- `docs/00` 只说设计取舍与理由，不写操作步骤。
- `docs/01` 只说操作步骤，不复述理由。
- `docs/02` 只说模型档位与角色的对应关系。
- `docs/03` 只说角色职责与边界。
- `docs/04` 只说记忆的分层、预算、读写规则。
- `docs/05` 只说知识库 schema 与接入方式。
- `docs/06` 只说网络相关注意事项。
- `docs/07` 只给症状到排查路径的映射，不解释原理。
- `docs/08` 只记真实踩坑与修法。
- `config/` 下的文件是唯一事实源：文档引用配置时链接到文件，不复制内容。
- 同一事实只允许在一个地方定义，其他位置用链接。
